# Public Alpha 15 分钟首次使用测试

## 目标

验证一名没有参与 EvalPilot 开发的用户，能否在不修改源码的情况下完成：

`安装 → 环境检查 → 添加项目 → 核心评测 → 打开并解释首份报告`

这不是功能演示。观察者不能代替用户点击，也不能提前解释界面选项。

## 成功门禁

- 至少 5 名外部测试者。
- 首次评测完成率不低于 80%。
- 完成用户的中位耗时不超过 15 分钟。
- 隐私或安全 P0 为 0。
- 完成后，用户能用自己的话说出：
  - 当前产品能否上线；
  - 最严重的问题是什么；
  - 下一步应该做什么。

## 测试前准备

测试者需要：

- macOS；
- Node.js 20.19.0 或更高版本；
- 一个可以在本机启动的 Web 项目；
- 项目文件夹、启动命令和本地网址。

观察者需要：

- 一个匿名编号，例如 `tester-01`，不记录姓名或邮箱；
- 计时器；
- `public-alpha-scorecard-template.csv` 的一份副本。

不要收集源码、`.env`、Token、Agent 对话、完整截图、Trace 或 `~/.evalpilot-local`。

## 测试脚本

### 1. 开始计时

只给测试者以下目标：

> 请安装 EvalPilot Local，添加你准备好的 Web 项目，完成一次核心评测并打开报告。遇到问题时先按页面提供的恢复动作处理。

不要解释 Dashboard 内的按钮或选项。

### 2. 安装和环境检查

测试者自行执行：

```bash
npm install --global evalpilot-local@alpha
evalpilot doctor
evalpilot dashboard
```

如果页面明确提示 Chromium 缺失，允许测试者按照页面指引安装；观察者不能直接给出命令。

记录：

- 是否理解 `doctor` 结论；
- 是否成功打开 Dashboard；
- 是否需要观察者解释。

### 3. 添加项目

测试者自行选择项目，并确认：

- 项目名称是否正确；
- 启动命令是否合理；
- 本地网址是否指向准备好的项目。

记录：

- 使用了智能候选、文件夹选择还是手动路径；
- 是否出现端口、网址或启动失败；
- 页面提供的恢复动作是否有效。

### 4. 运行核心评测

测试者使用系统推荐方案开始，不要求展开高级设置。

记录：

- 是否理解核心评测会检查什么；
- 是否能判断当前运行到哪一步；
- 失败时能否找到继续或恢复入口。

### 5. 打开报告

停止计时的条件：

- 对应评测状态为完成；
- 报告页已经打开；
- 用户能看到上线判断和问题列表。

随后询问：

1. 你认为这个产品现在能上线吗？
2. 最需要处理的问题是什么？
3. 你下一步会做什么？

只记录答案是否与报告一致，不记录业务敏感内容原文。

## 结果分类

| 结果 | 定义 |
|---|---|
| `completed` | 15 分钟内独立打开对应报告，并正确回答三个理解问题 |
| `completed_with_help` | 打开报告，但观察者解释过界面或命令 |
| `blocked_product` | 被 EvalPilot 的安装、交互、错误恢复或错误信息阻塞 |
| `blocked_target` | 被测项目本身无法启动、网址错误或缺少必要环境 |
| `stopped_privacy` | 继续操作可能暴露秘密或私人数据，测试立即停止 |

完成率只计算 `completed`；`blocked_target` 单独报告，不能伪装成 EvalPilot 成功或失败。

## 严重度

- P0：泄露秘密、修改目标源码、危险操作无确认、错误项目被执行。
- P1：无法完成首次评测，且页面没有可行恢复动作。
- P2：需要观察者解释才能继续，或报告无法支持决策。
- P3：文案、布局或效率问题，不阻断闭环。

## 每轮结束

1. 将匿名结果写入计分表。
2. 可复现的产品问题使用 GitHub 的 “Public Alpha test feedback” 模板提交。
3. 删除临时复制的日志和未脱敏截图。
4. 5 轮结束后计算完成率、中位耗时、P0/P1 数量。
5. 门禁未通过时继续发布 `alpha`，不得发布稳定版。
